# Конспект по презентациям «Процессор: теория» и «Рабочий цикл процессора»

## Часть I. Архитектура и элементы процессора

### 1. Элементы процессора

Процессор включает:
- **Дешифратор команд** (принимает КОП — код операции);
- **Операционные устройства** (АЛУ и др.);
- **Устройство управления (УУ)**;
- **Регистры**;
- **Транслятор адресов операндов**;
- **Внутренняя и внешняя шины**.

**Типичный микропроцессор** имеет выводы: адресация, данные, управление шиной, арбитраж шины, состояние, прерывания, тактовая частота, питание (+5 В), земля.

Историческая справка: первый микропроцессор **Intel 4004** (1971 г.) — мощность как у ENIAC, стоил 200 долларов, 2300 транзисторов, тактовая частота 108 кГц.

### 2. Операционные устройства

Виды: целочисленная арифметика, логические операции, сдвиги, десятичная арифметика, числа с плавающей запятой, графические операции.

**Структурный базис:**
- **Регистры** — хранение слов данных (линейка триггеров);
- **Шины** — связь регистров, передача слов;
- **Комбинационные схемы** — вычисления по управляющим сигналам.

**Классификация регистров:**
- программно-видимые явно;
- видимые косвенно («теневые» регистры дескрипторов сегментов);
- внутренние специального назначения (адреса памяти, данных);
- внутренние для промежуточных результатов.

**АЛУ** — комбинационная схема (без элементов памяти): два входа-операнда, один выход-результат. Состав: логическое устройство, полный сумматор, декодер операции. Многоразрядное АЛУ строится из 1-битных АЛУ с цепью переноса.

**Простейшие операционные устройства:** пересылка (`mov R1,R2`), сдвиг (`rol R0`), сложение (`add R0,R1`).

**Магистральная структура:** узел РОН → мультиплексоры (Mux A, Mux B) → операционный блок (ОПБ) → магистрали A, B, C. Типы: трёхмагистральное, двухмагистральное, одномагистральное ОПУ.

### 3. Устройство управления

**Функции УУ:** выборка команды из ОЗУ, дешифрация КОП, формирование адресов операндов, выборка операндов, передача в операционное устройство, выполнение операции, запись результата, инициирование ввода/вывода, реакция на прерывания.

**Понятия:**
- **Микрооперация** — элементарное действие за один такт;
- **Микрокоманда** — совокупность одновременно выполняемых микроопераций;
- **Микропрограмма** — последовательность микрокоманд машинного цикла.

**Состав УУ:**
- управляющая часть: регистр команды, микропрограммный автомат (+ дешифратор команд), узел прерываний и приоритетов;
- адресная часть: операционный узел УУ, регистр адреса, счётчик команд.

**Два типа микропрограммных автоматов:**

| | Жёсткая логика | Программируемая логика |
|---|---|---|
| Принцип | Однажды соединённые логические схемы; сигналы «привязаны» к тактам | Наличие памяти микропрограмм; каждой команде — своя микропрограмма |
| Управление | Счётчик тактов + дешифратор тактов + логические схемы формирования сигналов | Преобразователь КОП → формирователь адреса микрокоманды → регистр адреса → память микропрограмм → регистр микрокоманды → дешифратор |
| Особенности | Сброс счётчика тактов в Т1 по окончании цикла; учитываются флаги | Идея Мориса Уилкса (1951); к 70-м стала преобладающей, в современных процессорах от неё отказались ради производительности |

**Микрокоманды:** GATE (биты-стробы вентилей), TEST (проверка бита регистра и переход по адресу).

### 4. Архитектуры системы команд

Важный вопрос — где хранятся операнды и как к ним доступ.

**Стековая архитектура:** LIFO, операции push/pop, запись только в вершину. Обратная польская запись (Я. Лукашевич): `a = a b + a c x +`. Снижает издержки на адресацию.

**Аккумуляторная архитектура:** аккумулятор хранит результат и один из операндов; второй — из памяти через регистр данных. Команды `load x`, `store x`. Плюсы: короткие команды, простое декодирование. Минус: многократные обращения к памяти.

**Регистровая архитектура:** регистровый файл (РОН), размер = машинное слово, доступ по номеру. Подвиды команд: регистр-регистр, регистр-память, память-память. CISC — мало РОН, RISC — много (до сотен). Плюсы: компактный код, высокая скорость. Минус: длинные инструкции.

**Архитектура с выделенным доступом к памяти (Load/Store):** память доступна только командами `load` и `store`; обработка — только в регистрах. Характерна для RISC (Sun SPARC, MIPS R10000, DEC Alpha, PowerPC), команды 32 бита, трехадресный формат.

**Иерархия АСК:** аккумуляторная → регистровая (IBM 360) → CISC (VAX, Intel) / Load-Store (Cray 1) → RISC (Mips, Sparc) → VLIW (Itanium).

### 5. Процессор Intel 8086

**Структурная схема:** устройство обработки (РОН ax,bx,cx,dx; si,di,sp,bp; АЛУ; сумматор; регистр флагов) + устройство сопряжения с шиной (сегментные регистры cs,ss,ds,es; указатель команд ip; сумматор адреса; очередь команд; управление шиной). Внутренняя шина 16 бит.

**Регистр флагов:** CF (перенос), PF (чётность), AF (вспомогательный перенос), ZF (ноль), SF (знак), TF (трассировка), IF (разрешение прерываний), DF (направление цепочечных команд), OF (переполнение).

**Сегментная организация памяти:** физический адрес = сегментный регистр × 16 + смещение (offset), 20-битный адрес. Модели памяти: Tiny, Small, Medium, Compact, Large, Huge. Команды: `int iA`, `int far *pA=&iA`, `lea bx, iA`, `les bx,pA`.

### 6. Команды и их кодирование

**Форматы команд:** с операндом в регистре; с постбайтом; со смещением; с прямой адресацией; сдвиги; условный переход; неявная адресация и управление; ввод-вывод из порта.

**Особенности i8086 (CISC):** всего 538 команд (210 целочисленных, 85 с плавающей точкой, 57 MMX, 16 MMX Pentium III, 70 XMM). Базовая структура — двухоперандная (один операнд в регистре). Длина команды 1–15 байт. Сложные многокомпонентные способы адресации. Неортогональная регистровая модель. Команды пересылки не изменяют признаки.

### 7. Конвейер и сегментация

Конвейер: устройство обработки (УО) и устройство сопряжения с шиной (УСШ) работают параллельно над разными командами (К1, К2, К3, К4).

## Часть II. Рабочий цикл процессора

### 1. Общие положения

**Программа** — последовательность команд преобразования входных данных в выходные. Команды и данные хранятся в оперативной памяти (ОП), выполняет команды процессор. Связь: системная шина (данные, адрес, управление).

**Представление данных:** двоичная система, форматы с фиксированной и плавающей точкой; символы — двоичные коды; двоичные векторы — беззнаковые целые.

**Представление команд:** код операции + адреса операндов. Система команд — набор команд конкретного процессора (арифметические, логические, пересылки, передачи управления, ввода-вывода). Пример — система команд КМ1816ВЕ51 (семейство x51): ADD, ADDC, SUBB, INC, DEC, MUL, DIV, DA и др.

### 2. Аппаратное обеспечение (упрощённая схема)

**Регистры процессора:**
- **СчАК** — счётчик адреса команды;
- **РК** — регистр команд (КОП, A1, A2);
- **П1 (аккумулятор)**, **Р2** — регистры АЛУ;
- **ПортА** — порт адреса, **ПортД** — порт данных;
- **УУиС** — устройство управления и синхронизации;
- **DC** — дешифратор КОП.

**Регистры ОП:** РАОП (регистр адреса), РСОП (регистр слова).

**Чтение из ОП:** адрес в РАОП + сигнал ЧтОП → данные в РСОП → порт данных.
**Запись в ОП:** адрес в РАОП + данные в РСОП + сигнал ЗпОП.

### 3. Этапы рабочего цикла (на примере двухадресной арифметической команды)

**1 этап. Выборка команды из ОП**
1. `y1`: ПортА := СчАК (адрес команды на шину адреса);
2. `y2`: ЧтОП (чтение);
3. `y3`: РК := ПортД (команда в регистр команд).

**2 этап. Выборка операндов**
- 2.1. Первый операнд: `y4`: ПортА := A1; `y2`: ЧтОП; `y5`: Р1 := ПортД (в аккумулятор).
- 2.2. Второй операнд: `y6`: ПортА := A2; `y2`: ЧтОП; `y7`: Р2 := ПортД.

**3 этап. Выполнение операции в АЛУ**
`y_i^АЛУ`: КОП → DC → x_i → УУиС → y_i → АЛУ. Результат помещается в аккумулятор Р1. АЛУ выставляет **Z_АЛУ** (ШАЛУ(8)): 1 — занято, 0 — свободно; процессор ожидает 0.

**4 этап. Запись результата в ОП** (на место первого операнда)
`y8`: ПортД := Р1; `y4`: ПортА := A1; `y9`: ЗпОП.
Дополнительно: `y11`: РПР := Coder(ШАЛУ(0:3)) — для add, sub, inc, dec, and, or, xor; `y12`: РФ(0:4) := ШАЛУ(3:7) — флаги исключительных ситуаций.

**5 этап. Продвижение СчАК**
`y10`: СчАК := СчАК + L (L — длина команды в байтах). Может выполняться сразу после выборки команды.

**Микропрограмма работы процессора** — повторение этапов; по включению (Set) вырабатывается `y0`: установка СчАК на начальный адрес; Reset выключает УУиС.

### 4. Признаки результата и флаги

**ШАЛУ (унитарный код):** 0 — Р1=0; 1 — Р1<0; 2 — Р1>0; 3 — переполнение с фиксированной точкой; 4 — переполнение порядка; 5 — исчезновение порядка; 6 — потеря значимости; 8 — деление на ноль.

**Coder** преобразует ШАЛУ(0:3) в 2-битный позиционный код РПР: 00 — ноль, 01 — меньше, 10 — больше, 11 — переполнение.

**РФ** (регистр флагов прерываний) запоминает флаги исключительных ситуаций; его разрядность больше числа флагов АЛУ (прерывания также от таймеров, внешних устройств).

### 5. Команды перехода

После арифметической команды СчАК всегда продвигается — переход к следующей команде. Для ветвлений и циклов — команды передачи управления.

**Команда условного перехода по маске:**
- КОП — РК(0:7);
- М (маска) — РК(8:11): 0000 — нет операции (NOP); 1111 — безусловный переход (JMP); иначе — проверка РПР;
- А (адрес перехода) — РК(12:n).

Соответствие маски: PK(8)=0 ↔ РПР=00; PK(9) ↔ <0; PK(10) ↔ >0; PK(11) ↔ ППФТ (переполнение).

**Логика:** если М или А — нули, перехода нет; если М — все единицы, переход обязателен; если признак результата совпадает с кодом в М, продвинутый адрес в СчАК замещается адресом А. Признак результата не изменяется.

Разрядность адреса: **N_A = log₂ E_оп** (объём ОП в байтах); такую же разрядность имеют СчАК и поле А.

Осведомительный сигнал x4 вычисляется комбинационной схемой (DC + вентили И + ИЛИ) по РПР(0:1) и РК(8:11).

### 6. Прерывания

**Назначение:** поддержка системы прерываний — в процессор вводятся регистр флагов (РФ) и регистр-указатель стека (УС).

**Типы прерываний:**
- **исключения** (деление на ноль, переполнение и т.п.) — как правило, не маскируются;
- **от внешних устройств** (ввод/вывод, клавиатура) — могут маскироваться;
- **от таймера** — переключение между программами в мультипрограммном режиме (квант времени, например 1/30 с).

**Аппаратная поддержка:** РФ (флаги прерываний) и РМ (регистр масок) — i-й бит соответствует i-й причине; установка бита в РМ отменяет обработку.

**Таблица векторов прерываний (ТВП):** первые n слов ОП; в i-м слове — команда `JMP A_i` на программу обработки.

**Стек:** LIFO; УС указывает на верхушку (верхний свободный элемент). Запись: ОП[УС] := ...; УС = УС + 1. Извлечение: УС = УС − 1; ... := ОП[УС].

**Алгоритм обработки прерывания:**
1. ОП[УС] := СК; УС = УС + 1 (сохранение адреса возврата);
2. СК := i (адрес слова ТВП);
3. Выполняется `JMP A_i`: СК = A_i;
4. Последовательно выполняются команды программы обработки;
5. `RETI`: УС = УС − 1; СК := ОП[УС] — возврат к прерванной программе.

Если единиц в РФ несколько — процедура опроса с учётом приоритетов (курс «Операционные системы»).

**Недостаток векторной системы:** сохраняется только адрес возврата; сохранение/восстановление РСФ и РОН (например, РПР) — задача программиста. В некоторых системах сохраняется «Слово состояния программы» (ССП/PSW).

## Ключевые выводы

1. Процессор = дешифратор команд + операционные устройства (АЛУ, регистры) + УУ + шины; управление реализуется микропрограммным автоматом (жёсткая или программируемая логика).
2. Архитектура системы команд определяет, где хранятся операнды: стек, аккумулятор, регистры, выделенный доступ к памяти (Load/Store).
3. Рабочий цикл: выборка команды → выборка операндов → выполнение в АЛУ → запись результата → продвижение СчАК; управление — сигналами y_i, контроль — осведомительными x_i и Z_АЛУ.
4. Признаки результата (РПР) и флаги исключений (РФ) обеспечивают условные переходы и обработку прерываний.
5. Прерывания реализуются через ТВП, стек и регистры РФ/РМ/УС; возврат — командой RETI.
